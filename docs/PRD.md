## 1. 專案概述

### 1.1 背景與動機

賭場類型遊戲（如賽特／骰寶）中，玩家長期因缺乏系統化策略而持續虧損。本系統旨在提供一套**智能化選房與操作輔助平台**，讓使用者能依照即時數據選擇最佳遊戲房間，並透過自動化規則確保資金安全、穩定出金，避免因情緒化操作或爆倉雪球效應而砍光本金。

### 1.2 目標用戶

| 用戶類型 | 描述 |
|----------|------|
| **一般玩家** | 希望穩定獲利、不懂自行分析數據的休閒玩家 |
| **進階玩家** | 了解基本策略，需要系統協助自動化執行與出金管控 |
| **資金管理者** | 代操他人帳號，需嚴格控制虧損上限與出金節奏 |

### 1.3 核心價值主張

- ✅ **一定要出金**：透過停損機制保住本金，以正期望值策略穩定獲利
- ✅ **不能虧本**：嚴格的風控規則，觸發停損點即自動停止操作
- ✅ **降低人為誤操作**：自動化選房與下注，減少情緒干擾
- ✅ **快爆預警**：提前偵測分時異常，避免在危險房間持續押注

## 2. 功能需求

### 功能一：智能選房（Room Selection）

**描述**：系統根據各房間的歷史開獎紀錄、賠率、當前趨勢，自動推薦最佳進場房間。

**使用者故事**：
> 作為一名玩家，我希望系統幫我篩選出當前最適合進場的房間，以便我不需要花時間手動分析每間的走勢。

**功能細節**：
- 顯示所有可選房間列表，含即時勝率評分
- 依據趨勢指標（連莊率、翻轉頻率）排序推薦
- 玩家可設定偏好（保守 / 積極）篩選房間
- 支援手動選房或採用系統推薦

---

### 功能二：穩定出金管理（Withdrawal Management）

**描述**：設定每日 / 每局出金目標，達標後自動提示停止或鎖定帳號操作，確保已獲利資金安全出場。

**使用者故事**：
> 作為一名玩家，我希望系統在我達到今日獲利目標後提醒我出金，以便我不會因繼續貪玩而把獲利吐回去。

**功能細節**：
- 設定每日出金目標金額（例：+5%、+500元）
- 達標後跳出鎖定提示，需手動解鎖才能繼續
- 記錄每次出金紀錄，圖表顯示週期性盈虧

---

### 功能三：自動設定停損點（Auto Stop-Loss）

**描述**：依據初始資金，系統自動計算建議停損金額，並在虧損達到門檻時強制停止所有操作。

**使用者故事**：
> 作為一名玩家，我希望系統在我虧損一定比例後自動停止下注，以便我不會在情緒激動時繼續加碼雪球。

**功能細節**：
- 設定初始本金後，系統建議合理停損比例（例：虧損≥20% 即停）
- 可手動調整停損金額或百分比
- 觸發停損後：自動暫停操作、發出警報、記錄原因
- 可設定「冷靜期」（例：觸發後鎖定 30 分鐘）

---

### 功能四：自動操作（Auto Play）

**描述**：根據玩家預先設定的策略（如：馬丁格爾、固定倍率），系統自動執行下注動作，無需手動操作每局。

**使用者故事**：
> 作為一名進階玩家，我希望系統依照我設定的策略自動下注，以便我可以同時管理多個帳號或避免反應太慢錯過時機。

**功能細節**：
- 支援多種下注策略：固定金額、馬丁格爾、1-3-2-6 系統
- 可設定連敗上限（超過即停止自動操作）
- 操作日誌即時顯示每局結果與倉位變化
- 一鍵啟動 / 暫停自動操作

---

### 功能五：快爆分時提前通知（Burst Alert Notification）

**描述**：即時監控各房間分時走勢，偵測到異常爆倉風險前，提前推送警告通知給玩家。

**使用者故事**：
> 作為一名玩家，我希望在某個房間即將出現快爆（短時間大幅異常）之前收到通知，以便我可以提前離場或調整策略。

**功能細節**：
- 監控每分鐘開獎結果，計算偏差指標
- 若偏差超過閾值（可設定），觸發「快爆預警」
- 通知方式：頁面彈窗警告、音效提示
- 提供快爆歷史紀錄，用於策略回測

## 3. 非功能需求

### 3.1 技術限制

| 項目 | 規格 |
|------|------|
| 後端框架 | Flask + Python |
| 模板引擎 | Jinja2 |
| 資料庫 | SQLite（本地輕量部署） |
| 前端 | HTML / CSS / JavaScript（Vanilla） |
| 部署環境 | 本機或小型 VPS，無需大型雲端基礎架構 |

### 3.2 效能需求

- 房間數據刷新間隔：≤ 5 秒
- 快爆預警觸發延遲：≤ 2 秒
- 單一使用者操作響應時間：≤ 500ms

### 3.3 安全考量

- 帳號登入需身份驗證（Session-based Auth）
- 停損與出金設定需二次確認，防止誤觸
- 所有操作紀錄不可刪除（Append-only Log），確保追溯性
- 夜間模式自動暫停（可選設定），防沉迷機制

## 6. 開放問題（待討論）

> [!IMPORTANT]
> 以下問題請團隊討論後填寫，會影響後續設計方向

1. **數據來源**：房間的開獎紀錄是手動輸入、爬蟲抓取，還是串接第三方 API？
2. **自動操作的實際執行**：系統是「建議下注」還是「真正代替玩家下注」？後者需要與平台 API 整合。
3. **多用戶支援**：MVP 只支援單一帳號，還是需要多帳號登入？
4. **通知管道**：除頁面彈窗外，是否需要 LINE / Email / SMS 通知？
5. **合規性**：系統使用場景是否有法律合規疑慮需提前確認？
